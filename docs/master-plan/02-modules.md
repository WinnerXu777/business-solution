# Product modules

This is the full Toronto release catalog. Availability follows the selected delivery schedule and the release checks for each module. Each has a native implementation and can use compatible premium services through the same [provider interfaces](01-architecture.md#provider-abstraction). Each runs through shared [governance](05-governance-security-compliance.md), [metering](06-pricing-packaging.md) and the [typed tool gateway](01-architecture.md#execution-and-failure-handling). The [parallel calendar](03-roadmap.md) gives each module its own workstream.

Examples of how the modules work together:

- A caller verifies their identity. Voice uses the same order lookup as chat and MCP. The result comes from the tenant's chosen ERP.
- A purchaser submits a requisition. The bot drafts a PO, the approver confirms exact lines and terms, and the ERP records the approved purchase once.
- A CRM admin publishes a win-back workflow. The runtime checks marketing permissions for each account and logs every accepted send. Collections uses its own templates, purpose and approval policy. CRM shares opt-outs and holds with all collections channels.
- A fraud analyst confirms an eventual outcome, a planner checks a demand interval, and an account manager corrects a suggested segment. Those outcomes feed separate [model evaluations](04-data-ml-plan.md).
