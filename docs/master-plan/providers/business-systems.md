# Business systems and connector roadmap

Live web browsing was available. Sources checked 24 November 2026. Scope is production integration for Toronto/Canada first, then the US, with a small native ERP and CRM on Odoo Community or ERPNext. Pricing here covers developer access, API usage and access-related gates. The earlier ERP/CRM subscription and implementation analysis is in [SMB ERP CRM AI bot bundle](../../../reports/SMB%20ERP%20CRM%20AI%20bot%20bundle.md).

**Decision.** Start with QuickBooks Online, HubSpot, Microsoft Graph, Gmail, Stripe and Shopify. Add a Canadian payments and purchasing lane, then the next accounting, CRM and support systems. Keep the native ERP/CRM and the first-party connector contract independent of the aggregation vendor. Use official MCP for bounded interactive tools, and vendor APIs for durable sync, reconciliation and controlled writes.

### Reading the tables

- **U** in the adoption column means provider share among SMBs is unverified in **both Canada and the US**. Any proxy shown retains its own geography, population and denominator. No estimate is extrapolated across countries or products.
- **Unverified** means the cited public material did not establish the detail. Confirm it with the vendor for the actual product, country, plan and distribution model. **Bundled** means the documented API is tied to a product or usage plan and no separate API meter was found. **Quote** means obtain commercial confirmation before committing. **MCP unverified** covers both official and community availability unless an implementation is named. Provider-authored, community, paid third-party, documentation-only and limited-access MCP are called out separately.
- API quality is an engineering assessment from the interfaces, schemas, change feeds, sandbox and operational constraints described. Listing review, OAuth verification and production credential approval are separate. Webhook capability is object- and product-specific.

Promote a connector to first-party implementation when a paid workflow needs reliable posting, custom fields, reconciliation or an event-latency guarantee the aggregator cannot deliver.

## Connector and MCP contract

Use one versioned connector interface for native ERP/CRM, direct provider, unified API and file/bridge adapters. The UI, background workers and MCP server call the same policy-gated service. Each tenant chooses the system of record by domain and direction. For example, a native ERP can own POs while QBO owns posted accounting and Stripe owns processor settlement events.

| Surface | Required behaviour |
|---|---|
| Manifest and connection | Versioned manifest records provider, flavour/edition, environment, region, auth mechanism and scopes, resource/action capabilities, webhook/delta/poll support and quota hints. Make capabilities explicit per connection and role. Implement `connect`, `health`, `refresh`, `revoke` and `disconnect`. Derive tenant, actor and allowed connection binding server-side. Key resources by tenant, connection, provider organisation and external ID. Separate sandbox from production. Vault and rotate credentials, serialize refresh, enforce least privilege, and record consent and disconnect/delete state. |
| Canonical models | Start with company/contact/deal, item/order/fulfilment, supplier/PO/receipt, invoice/credit/payment/allocation, bill, ticket and email. Use decimal amounts and ISO currency, source timezone and timestamps, line-level taxes and external tax codes. Preserve source ID, version/ETag, external links, field provenance and safe provider extensions. Explicitly distinguish unavailable, null, stale and deleted. Assign field ownership and match by persisted identity or human-reviewed mapping. |
| Reads and sync | Provide `get`, cursor-paged `list` and `pullChanges`; support initial backfill, high-watermarks with overlap, tombstones or periodic deletion checks, and checkpointed replay. Verify inbound signatures against raw bodies or use the provider's authenticated transport, bind events to the installed account, accept to durable queue, deduplicate and fetch authoritative state when needed. Normalise events to versioned envelopes with provider/connection, object, external ID, event ID, occurrence time, received time and cursor where offered. Renew subscriptions and perform periodic drift reconciliation. |
| Controlled writes | Provide `prepareAction` and `executeAction`. Validate object and field permissions, draft/posted state, source version, amount, currency, tax and policy. Bind explicit approval when needed to immutable action arguments, actor/tenant, expected version and expiry. Idempotency key and write ledger/outbox are required for side effects, using native idempotency when available. Reconcile unknown outcomes by external reference or read-after-write before retrying. Use posted invoice credit/void semantics and never auto-retry an ambiguous money movement. |
| Errors and visibility | Standardise typed failures such as `auth_required`, `permission_denied`, `rate_limited`, `conflict`, `validation_failed`, `unsupported`, `provider_unavailable`, `approval_required` and `outcome_unknown`. Include retry hints and redacted provider correlation IDs. Rate-limit per vendor quota dimensions, honour Retry-After, budget bulk/backfill separately and surface sync age, webhook lag, quota and write status. Retain auditable actor, intent, approval and provider result with secrets and sensitive payloads redacted. |
| MCP boundary | Publish a platform-owned remote Streamable HTTP MCP endpoint with negotiated protocol versions and spec-compatible OAuth discovery/access tokens. Validate audience and scopes on every request and keep upstream credentials internal. Offer small, versioned JSON-schema tools such as `list_open_invoices`, `get_order_status`, `draft_collection_email`, `prepare_purchase_order` and `get_action_status`. Return structured results with next cursor, as-of time, source and warnings. Expose only capability- and role-authorised tools. Use annotations as client hints and enforce policy in the service. Treat vendor messages/tickets and tool outputs as untrusted content. Vendor MCP tools enter through a scoped, allowlisted adapter. UI approval, accounting posting and cash movement remain governed by the same deterministic service. [MCP transport](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) · [MCP authorisation](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) · [MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) |
| Release acceptance | In permitted sandbox or pilot tenant, prove token rotation/revocation, tenant isolation, partial backfill restart, duplicate and out-of-order delivery, webhook outage recovery, quota recovery, deletes/voids, and unknown-write recovery. Compare ledger and processor totals for CAD/USD, credits and partial payments. Verify CA tax and privacy settings, disconnect/data export, and product-specific production approvals before general rollout. |

Research is based on public documentation, published terms and first-party studies. Production credentials, negotiated quotes, provider tool entitlements and exact event/field coverage were not exercised in live customer tenants.
