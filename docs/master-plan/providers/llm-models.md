# LLM and model services

**Research and pricing snapshot — 2026-11-24.** Live public provider documentation. Rates are USD before tax unless indicated. Text generation pairs are dollars per million uncached input / output tokens at standard pay-as-you-go rates, with the model and tier specified. Tool calls, reasoning tokens, cache writes, long context, throughput commitments and regional uplifts can change the bill. Published prices are examples, not quotes. **Unverified** means the public evidence reviewed did not establish the detail. **Quote** means obtain pricing for the named deployment before procurement. **ZDR** means zero data retention for the stated feature and scope. Data at rest, processing, telemetry, support and downstream tools are separate residency checks.

**Launch decision.** Own the API, tenant policies and usage ledger. Start with open weights on Canadian infrastructure for the default route, benchmark inexpensive managed models as controls, and offer separate, opt-in premium routes. Start with Canadian Bedrock Claude and Montréal Vertex Gemini as managed candidates. Keep company-specific knowledge in PostgreSQL and retrieval. Introduce tenant-specific adapters for repeatable profiling tasks once a holdout shows an improvement.

### Cost and margin model on 2026-11-24

**Planning mix:** 0.8M uncached input + 0.2M output tokens per 1M total, no cache or tools. Vendor rates above. Counts can differ by tokenizer and reasoning usage, so compare cost per accepted workflow in addition to tokens. Illustration adds **$0.10/M** variable gateway, logging and safety cost to each route. It excludes fixed platform labour, sales tax, payment fees, vector infrastructure and one-time training. Treat the resulting percentages as model-service contribution margins for the example, separate from gross margin of an SMB subscription.

Self-host illustration assumes $1.00 per provisioned GPU-hour and 1,000 aggregate input-plus-output tokens/sec at saturation while meeting latency SLO, per GPU at this token mix. Effective utilization includes idle and failover capacity. Cost/M = `1,000,000 × hourly cost ÷ (3,600 × achieved tokens/sec)`. Two continuously warm replicas at 730 hours/month imply $1,460/month in GPU cost and need ~2.92B total tokens/month for $0.50/M GPU cost, assuming $1/hour. This is ~56% of the illustrative fleet throughput. Real capacity needs a load test at target context lengths and with adapter mix, replicas, cold starts, quantization and prefix-cache behaviour. At this price/performance, even 100% utilization costs ~$0.28/M GPU-only, so an inexpensive eligible managed route can be cheaper. Run self-hosting for Canadian boundary, adapter control and predictable cost where justified by measured economics.

**Commercial model.** Include capped routine model usage in bot plans and sell direct API capacity separately. Treat $1.50/M blended as a planning target, then publish separate input/output rates or credits with generous limits on output and reasoning. Use minimum commitments for dedicated tenants whose idle capacity they reserve. Meter cache reads/writes, tools and reasoning where billable. Use a target contribution envelope, e.g. 60% for native and 20% for premium. At 20%, the premium revenue floor is `(upstream + allocable variable costs) / 0.8`. At GPT-6.2 Sol list and the above mix that is $27.125/M, before fixed support costs. A 20% markup yields ~16.7% margin before overhead. Stress-test provider rate changes, FX, long contexts, output-heavy usage, retries, tool fan-out and per-tenant spend. [Packaging baseline](../06-pricing-packaging.md)

## Customer profiling — when fine-tuning pays

| Need | First choice | Decision rule |
| --- | --- | --- |
| Current order history, CRM notes, activity and facts specific to an account | SQL filters/features and tenant-scoped RAG, with record citations and date cutoffs | Refresh or delete underlying records and derived embeddings. Keep mutable facts and identifiers out of adapter weights. |
| A handful of labels or a taxonomy that is still changing | Strict JSON schema with deterministic fields, tenant-specific examples and a prompt-based classifier | Version labels before generating more annotations. For structured segmentation with fixed features, benchmark rules or a small supervised classifier before the LLM. |
| Stable taxonomy, persistent extraction errors, many similar cases, or expensive few-shot prompts | Tenant-specific supervised LoRA for schema and label behaviour, with SQL/RAG evidence at inference | Start after collecting hundreds of diverse adjudicated examples and adequate per-class holdout support. Tune if it improves held-out macro-F1, schema validity, evidence precision, abstention/calibration or reviewer time enough to pay back. |
| Rare labels, weak evidence, inconsistent reviewers or sensitive decisions | Abstain and review manually; improve data and rubrics | Keep permitted purpose, explainability and human review. Exclude sensitive traits and high-impact eligibility decisions from this feature per platform scope. |

**Experiment.** Begin with a commercially usable small-base checkpoint that supports the target adapter and in-region deployment. Split by account and time so variants of the same account cannot leak into evaluation. Compare rules, prompted base, RAG + prompt and RAG + LoRA on identical evidence and the same output schema. Pre-agree lift, e.g. five macro-F1 points or a measurable drop in reviewer minutes that repays setup within one quarter, with no material regressions on minority labels, French workflows, evidence citations or abstention. Track cost per accepted profile and drift. The business owners review output and approve publication. [Data and ML plan](../04-data-ml-plan.md#customer-profiling-and-segmentation)

**Serving and lifecycle.** Train and serve tenant-specific adapters in Canada for strict tenants. Prefer vLLM multi-LoRA on a shared base where the exact model supports it and the isolation tests pass. Give each adapter a signed tenant, region, data snapshot, base revision and evaluation record. Route by authenticated tenant, avoid shared prompt or adapter-state leaks, and allow rollback to prompted/RAG baseline. Treat weights and datasets as sensitive. Use scoped jobs, purpose-approved minimal training examples, expiry/deletion of jobs, datasets, artifacts and backups, and adapter retirement/retraining when required. No default pooling. Benchmark provider fine-tuning with synthetic or approved data where region and lifecycle are unsettled.

**Payback illustration on 2026-11-24.** If approved tuning, eval and serving overhead total $600 over a quarter and measured savings are $0.02 per accepted profile including reviewer time, break-even is 30,000 accepted profiles that quarter. Prompt token savings often contribute less than staff time or a measured move to a smaller model. Scope the first paid tune around an agreed volume and ongoing ownership of the label taxonomy.

**Before production procurement.** Record the exact SKU/model revision, order-form rate and effective date, quota, approved geographic endpoints, retention exceptions, subprocessors/access locations, deletion and backup windows, permitted data use, tool/observability egress, and tested failover behaviour. A single Canada region option does not establish the boundary across all features.
