# Roadmap

Use elapsed working time at 15–25 owner hours per week. Each milestone takes roughly 2–4 weeks and ends with a demo. Keep two or three implementation sessions active by default and use extra Codex sessions for independent fixtures, tests or review prep. The owner reserves time each week for reviews and integration. If a milestone keeps growing, split it at the next small demo and carry the remaining depth forward.

| Milestone and workstreams | Codex sessions that can run in parallel | Owner work | Demo to finish |
| --- | --- | --- | --- |
| **1. Full thin slice · 4 weeks.** One fictional distributor, one scenario through every module. | **A** builds seeded ERP/CRM reads, the gateway, REST/MCP, one approval and audit entry, a module flag and one usage counter. **B** builds chat and browser audio fixtures, a fixture LLM API with native/BYO routing, PR-to-PO and collections actions, Mailpit, simulated voice/SMS and a one-template workflow editor and runner. **C** wires an order to prepared rule and model fraud scores, a simple forecast and a fixture response from a profiling adapter. Use agreed schemas and fakes so each branch runs alone. | Choose the scenario and schema, assign package ownership, review permission and approval semantics, merge in dependency order and run the full flow from a reset. | In Compose, load a distributor, look up an order in REST, MCP, chat and browser voice, approve a draft PO and capture message previews. Run the win-back template, show fraud, forecast and profile outputs, switch model routes and verify the quota and audit trail. Add working models and richer channel handling in later milestones. |
| **2. Governance, records and connectors · 3–4 weeks.** | **A** deepens permissions, approval binding, the outbox and audit export. **B** builds ERP/CRM forms, movement and receipt tracking, contact IDs and consent history. **C** adds scoped REST/MCP tools and a read-only connector using fixtures and an accounting sandbox where available. | Decide which system owns each record, review authorization and migrations, inspect failure behavior and integrate connector tests. | Receive a PO in parts, reload a connector snapshot safely and see the same order in the portal and MCP. Prove workspace isolation, approval invalidation and duplicate-write protection. |
| **3. Chat, inbound voice and the LLM API · 3–4 weeks.** | **A** builds LangGraph chat, checkpoints and handoff. **B** builds browser audio, interruption and local speech. **C** builds the live native inference route, streaming and structured output, plus OpenAI/Anthropic and speech adapter contract tests. | Choose the open-weight checkpoint and evaluation examples. Run batch evaluations on the school V100 and smoke-test vLLM on the A100. If access is restricted, use the local quantized model or a BYO test route. Measure voice behavior on personal equipment, review provider egress and integrate one end-to-end test route. | Ask for the same verified order in chat and browser voice, interrupt playback and hand off. Compare the native model with a BYO test route or contract fixture. |
| **4. Procurement, collections email and the workflow builder · 3–4 weeks.** | **A** deepens PR-to-PO checks and approval. **B** builds collections drafting, replies and dispute holds in Mailpit. **C** builds the versioned editor and runner, with preview, conditions, delays and history. | Decide purchasing authority and outreach rules, review the editor and message copy, then test changes to balance, opt-out and approval after queuing. | Approve a PO once, collect a simulated reply in Mailpit and build a win-back workflow from scratch. Show an opt-out stopping a queued send. |
| **5. Outbound voice and SMS, entitlements and metering · 2–3 weeks.** | **A** builds simulated call and SMS dispatch, receipts, bounded scripts and the RingCX adapter contract. **B** builds module grants, allowance and usage views. **C** tests contact windows, shared cadence, revocation, spend limits and pause behavior across channels. | Choose channel rules and test caps, verify shared controls across native and BYO routes, and review any sandbox test personally. | A fictional reminder can move through email, simulated voice and SMS. A dispute or pause stops queued contacts. Retry a receipt and show one charge against the demo allowance. |
| **6. Fraud and forecasting · 3–4 weeks.** | **A** trains fraud candidates and wires review explanations. **B** builds weekly sales and SKU/location forecasts and rolling backtests. **C** makes dataset generation, artifact registration and reruns reproducible. | Check data rights, choose review capacity and evaluation measures, inspect leakage and errors, and decide which models the demo should show. | Compare trained fraud scores with rules at the same review capacity. Show forecast ranges and backtest results alongside seasonal and sparse-demand baselines. |
| **7. Fine-tuned profiling · 3–4 weeks.** | **A** builds the fictional account taxonomy, labels and held-out evaluations. **B** builds retrieval and the baseline profiler. **C** builds the A100 LoRA/QLoRA job, artifact registration, routing and rollback. | Review labels and the dataset split, fine-tune on the school A100 and evaluate on the V100. If access is restricted, train a smaller checkpoint on personal equipment or rent a GPU on demand. Inspect evidence, rare segments and failures, then integrate staff review. | Run baseline and fine-tuned profiling on the same unseen fictional accounts. Review a profile with citations and roll back to the baseline. |
| **8. Private Canadian demo · 2–3 weeks.** | **A** prepares Compose deployment and restore instructions. **B** builds the reset and full demo smoke check. **C** reviews adapter defaults and tests recovery, data boundaries and quota exhaustion. | Provision the VM in a personal account, set access and test credentials, measure the demo, run a restore and rehearse the full walkthrough. | Start from a clean Canadian VM, load the fixture distributor and complete the README demo. Restore it from a backup and confirm outbound traffic still goes to test destinations. |
