# Milestone 1 base

## Owner decisions

- **Scenario and data — default, owner may change.** Rivetquay Industrial Supply is a fictional Toronto distributor. The fixture clock is 2026-11-25 at 15:00 UTC. Amounts are integer CAD cents. Customer addresses use reserved `.example` domains and numbers use the fictional 555-01xx range. Spoolharbour is a second workspace for isolation checks.
- **Schema — default, owner may change.** Call envelopes use wire version `v1`. JSON Schema uses Draft 2020-12 and OpenAPI uses 3.1.0. The shared source is `packages/contracts/v1/shared.json` and the tool catalog is `packages/contracts/v1/tools.json`. Each tool has request, input, output and result definitions. The owner coordinates all contract, fixture, dependency lock, migration and integration changes with one writer at a time.
- **Permissions — default, owner may change.** The real transport will resolve tenant and actor from verified identity and reject mismatching claims. The fake verifies the supplied identities against fixture grants. Readers can read records, operators can initiate actions, and approvers can sign. Missing and cross-tenant records both return `not_found`. Disabled or exhausted entitlements stop new work.
- **Approval and retries — default, owner may change.** Approval binds tenant, requester, separate designated approver, tool, target, material SHA-256, source and policy versions, and one-hour expiry. A draft PO returns a pending grant. In the fake, the authorized approver can use it once through the PO approval tool. Message and workflow execution return `pending_approval` before approval. Tests can sign with `FakeGateway.approveFixture` and submit the approved input under a fresh key. A same-key retry of the same input returns the stored result. Keys are scoped to tenant, actor and tool. A material input mismatch returns `idempotency_conflict`. Unknown outcomes require reconciliation. The fake holds the consumed attempt and returns its stored outcome on retry.
- **Metering and routing — default, owner may change.** The fake counts one action per successful new tool outcome inside its module window. Audit entries contain IDs, source, decision and policy version. The two fixture routes use `fixture-native` and `fixture-byo`. Quota accounting and approvals are process-local fixture behavior.
