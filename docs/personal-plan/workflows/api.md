# Workflow builder API

Register the Fastify plugin exported by apps/api/src/workflows/index.ts. It mounts at /workflow-builder/v1 and uses a private Python subprocess. The default launcher uses the project's virtual environment. Set BS_WORKFLOW_BUILDER_PYTHON to override the interpreter. The milestone walkthrough and its existing /automation endpoints remain available through the original runner.

The host supplies a verified identity resolver, capability authorization, and an effect relay. Identity contains tenant ID, actor ID and kind, and current role names. Requests derive scope from that identity. Automation receipts run under the trigger creator's scope and recheck run permission at admission. The effect relay must verify current eligibility, authorization and entitlements again at dispatch. Enable polling with pollMs (minimum 1000 ms). Scheduled and delayed work uses epoch milliseconds internally.

## Trigger configuration

A trigger has id, definitionId, kind and optional values. Definitions declare exact input keys and types. Scheduled runs take their values from the trigger. Record events overlay recordId and an optional recipientId. The event producer must supply stable IDs for authoritative transitions and keep origin and record version checks at ingestion. Retrying a receipt with different values conflicts.

- Schedule triggers require expression, timeZone and catchUp. Optional maxRuns defaults to 10 with a maximum of 100. Cron uses five numeric fields with lists, ranges and steps. Day of month and day of week use the conventional OR rule when both are restricted. A skipped spring-forward minute emits no receipt. Both fall-back occurrences emit distinct UTC receipts. The latest missed UTC minutes are considered over a seven-day lookback. Skip discards missed minutes. Run-once starts the latest missed match. Run-all starts up to maxRuns missed matches in chronological order. All three policies also consider the current minute. Accepted slots advance a stored cursor. If a launch hits a quota, the selected slot stays pending for retry before the next scan.
- Event triggers require name. Invoice overdue and customer inactive triggers also require threshold in days, between 1 and 365. A source can supply beforeDays and days to indicate crossing. Stock below reorder point accepts beforeQuantity, quantity and reorderPoint. Missing before fields represent an initial observation. Other supported event names are listed in packages/core/src/workflows/triggers.ts.
- Webhook triggers reference secretRef. The host resolves the secret for the tenant. Send X-Workflow-Timestamp as epoch seconds and X-Workflow-Signature as sha256= followed by 64 hex characters. Compute HMAC-SHA256 over the UTF-8 bytes of the JSON array [tenantId, triggerId, timestampString], one literal period, then the exact request body bytes. Use compact JSON for the array. The timestamp must be within five minutes of server time. Each stable body id deduplicates within its trigger. The request body limit is 256 KiB.
- Manual runs target definitions whose first node declares the manual trigger. There is no trigger record to create for manual runs.

## Definition and effects

Definitions use the [shared Draft 2020-12 schema](../../../packages/core/src/workflows/definition.schema.json). The API validates with AJV and the worker checks the same supported schema vocabulary before publish or preview. The graph must start with one trigger, have unique reachable node IDs, and have at most 40 nodes. Each reference must be defined with the required type on every path reaching that input.

| Node kind                    | Behavior                                                                                                                                                                                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| trigger, mapping             | Start from the matching receipt or assign typed literals and field references.                                                                                                                                                                                                  |
| branch, switch               | Compare a typed field to a literal and select an edge.                                                                                                                                                                                                                          |
| loop, loop-end               | Iterate a string list within maxItems up to 50. Each body path must end at a matching loop-end. Iteration-local fields are reset on each iteration and disappear at exit.                                                                                                       |
| delay, wait-for-event        | Resume at a deadline or after an authenticated matching signal. At the deadline the timeout edge wins.                                                                                                                                                                          |
| ab-split                     | Uses a stable bucket derived from tenant, workflow, node and assignment key. Bucket choice stays stable across versions that retain the node ID.                                                                                                                                |
| throttle                     | Limits entries into a named bucket over a rolling window per tenant and definition. A full bucket delays the run.                                                                                                                                                               |
| human-task                   | Assigns a role and due date. The assignee completes it through the inbox. The timeout edge handles expiry.                                                                                                                                                                      |
| checkpoint                   | Stops until the requester ticks the run. A migration can occur before that continuation.                                                                                                                                                                                        |
| llm-draft                    | Calls the native /llm/v1/chat/completions route through an injected transport with no tool declarations and a 512-token output cap. Draft text is typed separately and reviewable as message body material.                                                                     |
| message                      | Supports email, SMS and voice. For invoice collections without a custom body, the adapter uses governed message.preview and collections channel send tools, which recheck consent, suppression and approval at execution. General customer messages require a governed adapter. |
| create-record, update-record | Submit a bounded record operation on an activity, case or order hold through the governed adapter.                                                                                                                                                                              |
| http                         | Calls a configured connector operation by ID with a record ID. Both graph validation and the adapter enforce the connector/operation allowlist.                                                                                                                                 |

Writes and connector calls proceed through prepare, sign and execute. Prepare returns the designated approver and expiry without delivering or mutating the target. The relay must bind the approval to the exact material, tenant, requester, designated approver and current policy and source versions. It must revalidate approval and policy immediately before effect execution, enforce consent and suppression on messaging, deduplicate on the supplied action key, and hold unknown outcomes for reconciliation. The supplied relay supports native collections and drafting. The optional fixtureWorkflowEffects handler simulates customer outreach, scoped records and the fixture-records lookup operation. It reads demo consent and stores its state in memory. Install it only in the synthetic environment. Other handlers require equivalent governance.

Migration requires equal input contracts and an identical checkpoint and ancestor graph, including completed loop bodies. Only changes after the checkpoint are eligible. The target version may be newer or older. The run keeps its ID, historical entries and bound start receipt. Additional defaults are 16 active runs and 100 new runs per UTC minute per tenant. Waiting and checkpoint runs count as active. Existing receipt retries consume no new run capacity.

The default fixture runner keeps state in memory. Set stateDirectory to an existing private directory to retain the worker state in SQLite and the trigger cursors and pending slots in an atomically replaced JSON file. The worker reacquires the single-host lock and restores due timers on startup. The launch order records pending slots before dispatch and removes them after acceptance so retries can reuse receipt keys across process restarts. An interrupted effect moves to unknown for reconciliation. The synthetic journal contains workflow inputs and review material, so use a restricted directory. Separate governed providers need durable grants and record state for approval-bound actions to survive a host restart.
