# Native LLM API

Mount the Fastify plugin exported from `apps/api/src/llm/index.ts`. Its routes already include `/llm/v1`. Point an OpenAI client at that base URL and give it a platform-issued key. Bots can use the same interface with a tenant-scoped service key.

## Endpoints

| Endpoint                                            | Supported requests                                                                                                                                                                                                                                                                                                                        | Response                                                                                                                                                                                                                                  |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /llm/v1/chat/completions`                     | One choice. Send a model alias and text messages with `system`, `developer`, `user`, `assistant` or `tool` roles. Supports prior assistant `tool_calls`, tool results, `temperature`, `tools` and `tool_choice` (`auto`, `none`, `required` or a named function). Use `max_completion_tokens` or `max_tokens` (default 256, up to 8,192). | A `chat.completion` with an assistant message, finish reason, resolved model ID and usage. Tools are returned as proposals. The caller authorizes and executes them through the governed tool gateway.                                    |
| `POST /llm/v1/chat/completions` with `stream: true` | Same request with optional `stream_options.include_usage`.                                                                                                                                                                                                                                                                                | SSE with `chat.completion.chunk` objects, assistant role, incremental text or indexed tool calls, finish reason, optional usage-only chunk and `[DONE]`. An error after streaming begins is a sanitized SSE error object followed by EOF. |
| `POST /llm/v1/embeddings`                           | Send an embedding model alias, one string or up to 128 strings, optional `dimensions` (up to 4,096) and optional `encoding_format` (`float` or `base64`).                                                                                                                                                                                 | A list of indexed vectors in input order plus the resolved model and prompt usage. Base64 encodes little-endian float32 coordinates.                                                                                                      |
| `GET /llm/v1/models`                                | Authenticated tenant key.                                                                                                                                                                                                                                                                                                                 | Model aliases from the two primary bindings, deduplicated. The lookup uses the binding catalog and makes zero provider requests.                                                                                                          |

Send the modern `tools` interface for function calls. The request subset accepts text content and currently excludes multimodal content, deprecated `functions`, token-ID embedding arrays, and extra OpenAI parameters.

### Structured output

Set `response_format` to an object with `type: "json_schema"` and `json_schema` containing a `name`, `schema`, and optional `strict`. The platform checks the generated JSON against the submitted schema even when `strict` is omitted. Supported Draft 2020-12 features include object properties and required fields, homogeneous arrays, enums and constants, numeric and length limits, bounded composition, and nonrecursive local `#/$defs/<name>` references. Regex keywords and external references are outside this subset. Provider feature limits still apply to the selected model.

A schema failure is an HTTP 400 if the schema is invalid or an HTTP 502 if the provider returns invalid content. Structured streams buffer up to 1 MiB and 8,192 events before emitting content. A turn ending in tool proposals may be followed by another request containing tool results to complete the structured response.

## Auth and routing

Supply `Authorization: Bearer <tenant-api-key>`. The injected `verifyApiKey(key, endpoint)` returns the authorized tenant for that endpoint or rejects the key. Tenant IDs, provider credentials and binding selection come from the server. The API resolves an immutable binding once per requested capability via `resolveBinding(tenantId, capability)`. Each route maps allowed aliases to pinned provider model IDs. The resolver enforces entitlement, data and region policy, route features, and spend policy.

Responses carry `x-request-id`. A resolved POST binding appears in `x-llm-binding-version` on success and subsequent errors. The model catalog includes `x-llm-binding-version-llm` and `x-llm-binding-version-embeddings` for the bindings it lists. Requests denied before a binding is resolved have no binding version.

Fallback is a single additional chat attempt on an explicitly opted-in fallback route in the same pinned binding. The resolver approves it under the tenant's data, region and spend policy. The alias must exist on both routes. Only an unavailable primary provider is eligible, before any response is exposed. Embeddings stay on their primary binding. Tool calls are proposals, including on fallback.

## Limits and usage

The milestone implementation uses per-tenant, in-process fixed windows shared by these endpoints. The defaults are 60 requests and 100,000 tokens per 60 seconds, with a 30-second request deadline. Authenticated retries and invalid requests count toward the request limit. Each provider attempt reserves an approved route-specific upper bound for prompt tokens and the requested completion limit. Outstanding reservations carry across a window boundary. Settlement charges actual usage in the active window or the full reservation when provider usage is unknown. Exceeding a request or token limit returns HTTP 429. A usage-sink failure blocks subsequent metered work for that tenant in the process.

The injected `emitUsage` receives one record per provider attempt. Use `eventId` for deduplication and `requestId` to correlate attempts with the response. The record also carries `attempt`, `tenantId`, `capability`, `bindingVersion`, `model`, `provider`, `route`, `priceVersion`, `chargeMode` (`native` or `byo`), and `outcome` (`succeeded`, `failed` or `cancelled`). `inputTokens` and `outputTokens` hold provider-reported totals or null. `budgetTokens` holds the reservation settlement and is independent of invoice charges.

Request audit records contain the endpoint, tenant, request ID, HTTP status, binding version, selected route and normalized error when present. Audit and usage records omit prompts, tool arguments, completions, embedding data, keys and raw upstream errors. A sanitized diagnostic logger can be injected for the host application.
